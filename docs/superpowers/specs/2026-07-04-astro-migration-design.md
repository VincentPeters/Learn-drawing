# Design: Migrate Draft30 to Astro

**Date:** 2026-07-04
**Status:** Approved pending user review
**Goal:** Replace the hand-rolled vanilla static site with an Astro project that pre-renders every page, moves lesson content into Markdown, and improves developer experience — while preserving the site's zero-bloat, works-offline character and existing users' localStorage progress.

## Why

The current site renders course maps and all 45 lesson pages **client-side** from JS data files via query params (`lesson.html?m=1&d=5`). That means no real per-lesson URLs, no SEO, nothing works without JS, and authoring means editing JS objects with HTML strings. The user wants: better developability, real pre-rendered pages, content as Markdown, and modern site features (search, view transitions) — deployed on **Cloudflare Pages**.

## Decision

**Astro** (latest stable), static output. Chosen over Eleventy (weaker typed content and DX) and SvelteKit/Next (app-framework overhead a content site doesn't need). Astro ships zero JS by default, so the built site stays as lean as the current one.

## Architecture

```
src/
  content/
    lessons/            # 45 Markdown files: m1-01.md … m2-15.md
    phases/             # 9 data files (id, module, name, color, blurb, lesson range)
  components/
    diagrams/           # each hand-authored SVG diagram → one .astro component
    LessonBlock.astro, CourseCard.astro, ProgressBar.astro, ThemeToggle.astro, …
  layouts/
    Base.astro          # head, inline theme script, nav, footer, view transitions
  pages/
    index.astro                   # landing page
    module-[m]/index.astro        # course map, pre-rendered for m = 1, 2
    module-[m]/lesson-[n].astro   # 45 pre-rendered lesson pages (getStaticPaths)
    reference.astro               # visual cheat-sheet + glossary
  styles/style.css      # existing design system, carried over ~unchanged
public/                 # favicon, redirect stubs
```

Everything is statically generated at build time (`output: 'static'`, the default). No adapter, no server code.

## Content model

- **Lessons collection** (`src/content/lessons/`): one Markdown file per lesson. Frontmatter carries the structured fields currently in `curriculum.js` / `module2.js`: `module`, `number`, `phase`, `title`, `diagram`, `objective`, `warmup[]`, `main[]`, `checkpoint`, `tip`. A Zod schema in `src/content.config.ts` validates every file — a typo or missing field fails the build.
- Prose fields that today contain HTML strings (`tip`, `objective`) become plain Markdown.
- **Phases collection**: 9 small data entries (5 for module 1, 4 for module 2) with `module`, `name`, `color`, `blurb`, and lesson range. Course maps are generated by joining lessons to phases.
- The `MODULES` registry (tag, title, subtitle, color, kit, storage key) moves to a small typed TS module shared by pages.

## Interactivity (stays vanilla)

- **Progress**: localStorage under the existing keys `draft30.progress.v1` (module 1) and `draft30.progress.m2` (module 2) — existing users keep their progress. Small plain `<script>` per page marks checkmarks, updates progress bars, and powers "continue where you left off". Pages are fully readable with JS disabled; scripts only enhance.
- **Theme**: existing light/dark behavior (OS preference + manual override in `draft30.theme`), applied by an inline script in `Base.astro` head to avoid flash.
- **Keyboard nav**: ←/→ prev/next across the whole 45-lesson sequence, preserved as a small script on lesson pages. Prev/next order is computed at build time and embedded in each page.
- No client framework, no hydration. The only third-party client code is Pagefind's search UI on the search page/modal.

## URLs & redirects

| New | Old |
| --- | --- |
| `/` | `/index.html` |
| `/module-1/`, `/module-2/` | `course.html?m=1`, `?m=2` |
| `/module-1/lesson-5/` … | `lesson.html?m=1&d=5` … |
| `/reference/` | `reference.html` |

Old entry points (`lesson.html`, `course.html`, `curriculum.html`, `module2.html`) remain as tiny static redirect stubs in `public/` that read query params and redirect client-side, plus `_redirects` rules on Cloudflare Pages for the param-less cases. Old links keep working.

## Modern features (in scope)

- **View transitions** between pages via Astro's ClientRouter — respects `prefers-reduced-motion`.
- **Search** via Pagefind: indexes all lesson pages and the reference sheet at build time; fully static, works offline, no external service. Exposed as a search box in the header.

## Deployment

- **Cloudflare Pages** via its GitHub integration: build command `npm run build`, output directory `dist/`. Deploys on every push; preview deployments per branch.
- The GitHub Pages workflow (`.github/workflows/pages.yml`) and `.nojekyll` are **removed**. Cloudflare is the single deploy target.
- CI: a lightweight GitHub Actions workflow runs `astro check` + `astro build` on push so broken content can't merge (Cloudflare will also fail the build, but CI surfaces it in PRs).

## Error handling

- Content errors: Zod schema fails the build with a pointer to the offending file/field.
- Broken lesson references (e.g., a diagram name with no component): build-time lookup throws during `getStaticPaths`/render — no silent 404s.
- Custom `404.astro` page (Cloudflare Pages serves it automatically).

## Testing & verification

1. `astro check` and `astro build` pass with zero errors.
2. Parity pass: click through landing → both course maps → several lessons (first/last of each module) → reference page in the dev server; verify diagrams, progress marking, theme toggle, keyboard nav, and "continue" behavior against the current site.
3. Progress-migration check: seed localStorage with the old keys, confirm the new site reads them.
4. Redirect check: old query-param URLs land on the right new pages.
5. Lighthouse spot-check on a built lesson page (perf/a11y/SEO ≥ current site).

## Out of scope

- PWA/offline service worker, image pipeline (site has no raster images), analytics, CMS.
- Content changes: lesson text migrates 1:1 (HTML strings converted to Markdown).

## Migration notes

- The 45 lesson Markdown files are generated by a one-off script that reads the existing JS data files and writes frontmatter + body — not hand-copied.
- `PLAN.md` and `README.md` stay; README's "Running it" section updates to `npm run dev`.
